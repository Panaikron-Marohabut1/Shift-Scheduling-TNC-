# Milestone 3 — ล็อกตารางเดือนก่อนและส่งออก CSV สำหรับ HR

**เป้าหมาย:** เมื่อถึง 00:00 น. วันที่ 1 ตามเวลาไทย ตารางเดือนก่อนจะแก้ผ่านแอปไม่ได้ HR เปิดดูตารางที่ปิดและประกาศใช้แล้วของทุกทีม และขอ CSV จากข้อมูลชุดเดียวกันได้

**กฎอ้างอิง:** [Business Rules หมวด 8 และ 9](../01-requirements/01-spec/2026-11-04-01-business-rules-master.md) และ [rule.md](../01-requirements/rule.md)

งานรอบนี้ใช้ข้อมูลสังเคราะห์ใน PostgreSQL แยกในเครื่อง เปิดทดสอบด้วย `ENABLE_LOCAL_MONTH_CLOSE=true` เท่านั้น

## 3A — บังคับล็อกที่ Backend

- [x] ตรวจเส้นทางเขียนตารางจากโค้ดจริง การอนุมัติสลับกะขั้นสุดท้ายเป็นทางเขียนตารางในฐานข้อมูลของแอปปัจจุบัน ส่วนการแก้แบบเดโม่บนหน้าเว็บใช้ข้อมูลในเบราว์เซอร์และแยกจากฐานกลาง
- [x] ทดสอบให้คำขอเดือนก่อนอนุมัติไม่ได้เมื่อถึงเที่ยงคืน แม้สร้างไว้ก่อนเปิดกฎใหม่หรือเปิดหน้าจอค้างอยู่ ตรวจด้วยว่าคำขอของเดือนเปิดยังทำได้
- [x] ตรวจวันที่ของกะและรอบเดือนของตารางจากข้อมูลที่ล็อกไว้ในธุรกรรม ตรวจซ้ำก่อนจบการบันทึก และคงเวอร์ชันเดิมถ้าถูกปิดกั้น

## 3B — ตารางปิดเดือนและ CSV ของ HR

- [x] ใช้ Role HR ที่ยืนยันตัวตนจาก Backend อนุญาตทุกทีม เปิดดูและส่งออกได้เฉพาะตารางเดือนก่อนที่ประกาศใช้แล้ว
- [x] หน้าตารางปิดเดือนและไฟล์ใช้ตัวอ่านข้อมูลส่วนกลางตัวเดียวกัน เรียงแถวแน่นอน มีสี่คอลัมน์ รหัสพนักงาน ทีม วันที่ตามตาราง และรหัสกะ
- [x] สร้าง CSV เมื่อ HR ขอไฟล์ เก็บเฉพาะหลักฐานการสร้างไฟล์ ผู้ขอ วันเวลา เดือน และเวอร์ชันตารางตามกฎเก็บหลักฐานของโปรเจกต์ ไม่เก็บสำเนาไฟล์
- [x] ทดสอบบทบาทอื่นถูกปฏิเสธ เดือนเปิด/ยังไม่ประกาศใช้ส่งออกไม่ได้ ข้อมูลจากทุกทีมและวันหยุดตรงกันทั้งหน้าเว็บและไฟล์ และไม่มีการนับว่าบันทึกลงเครื่องสำเร็จจากเหตุการณ์ฝั่งเซิร์ฟเวอร์
- [x] ทดสอบใน Chromium ด้วยบัญชี HR สังเคราะห์ และรีวิวแยกก่อนสรุปผล

ขอบเขตที่ต้องตรวจต่อก่อนเปิดจริงคือการเก็บข้อมูลประวัติให้คงเดิมเมื่อมีการเปลี่ยนรหัสพนักงาน ทีม หรือรหัสกะ การจัดเก็บตารางและหลักฐานตามนโยบายบริษัท และเส้นทางแก้ข้อมูลหลังปิดเดือนที่ HR จัดการนอกแอปตามที่ตกลง
